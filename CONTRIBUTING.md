# How to contribute

We'd love to accept your patches and contributions to Cluster Health Scanner (CHS).

## Contributor License Agreement

Contributions to this project must be accompanied by a Contributor License Agreement (CLA). You (or your employer) retain the copyright to your contribution; this simply gives us permission to use and redistribute your contributions as part of the project. Head over to <https://cla.developers.google.com/> to see your current agreements on file or to sign a new one.

## Discuss before implementing

- **Major changes:** For new features, architectural changes, or new scheduler integrations, open an [Issue](https://github.com/GoogleCloudPlatform/cluster-health-scanner/issues) first to discuss your idea with maintainers.
- **Minor changes:** Bug fixes, documentation updates, and small improvements can be submitted directly as pull requests.

## Development and pull request workflow

See the [Development guide](docs/development.md) for setting up your local environment, running `pre-commit` and unit tests, and submitting a pull request against the `develop` branch.

- All new features and bug fixes must include unit tests under `tests/`.
- Keep pull requests small, focused on a single change, and rebased on `develop`.
- Maintainers review pull requests on a best-effort basis (typically within 1-2 weeks).

## Community guidelines

This project follows Google's Open Source Community Guidelines: <https://opensource.google/conduct/>

## AI-assisted contributions

Submissions to this project may use coding assistance tools, including AI-generated code, as long as these submissions abide by the Contributor License Agreement's requirements. All contributions will be reviewed to ensure they meet project standards.
